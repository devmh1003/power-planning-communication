# 전력사업기획실 소통행사

행사 안내, 마음의 편지 작성, 인터넷 공개 게시판을 제공하는 GitHub Pages용 사이트입니다.

## 미리보기

압축을 풀고 `index.html`을 브라우저에서 열면 가상 데이터로 작성과 게시를 시험할 수 있습니다. 미리보기 편지는 새로고침하면 사라집니다. 로컬 HTTP 서버에서는 `?demo=1`을 붙여 열어도 됩니다.

## 실제 게시판 연결 및 배포

1. 행사 운영용 Supabase 프로젝트를 만든 뒤 SQL Editor에서 `supabase.sql` 전체를 실행합니다. 이전 버전을 설치했다면 이 SQL을 먼저 다시 실행해 기존 공개 읽기 권한을 회수한 뒤 새 화면을 배포합니다.
2. `config.js`의 `supabaseUrl`에 프로젝트 URL을, `supabasePublishableKey`에 `sb_publishable_`로 시작하는 공개 키를 넣습니다. 비밀 키는 GitHub에 올리면 안 됩니다. 행사 정보는 같은 파일의 `event`에서 관리합니다. 현재 일시는 2026년 11월 12일(목) 15:00이며 장소는 리움미술관입니다.
3. 새 GitHub 저장소(예: `power-planning-communication`)의 `main`에 압축을 푼 파일과 폴더를 올립니다. Pages에 필요한 파일은 저장소 루트에 있습니다.
4. 저장소의 **Settings → Pages → Deploy from a branch**에서 **main /(root)**를 선택하고 저장합니다. 배포 URL은 일반 프로젝트 저장소의 경우 `https://<계정>.github.io/<저장소>/`입니다.
5. 배포 후 가상 이름으로 편지를 작성하고, 시크릿 창에서도 같은 글이 보이는지 확인합니다. 시험 글은 Supabase Table Editor의 `public.event_letters`에서 삭제할 수 있습니다.

## 공개 범위와 운영

- 게시판에는 받는 사람 이름, 제목, 본문만 표시합니다. 작성자 이름은 운영 데이터베이스에 저장되며 공개 API의 읽기 권한에서도 제외됩니다. 받는 사람에게 이메일이나 알림은 발송되지 않습니다.
- 사번은 입력 형식만 브라우저에서 확인합니다. 전송·저장되지 않으며 사내 계정 인증 기능은 없습니다.
- 인터넷 방문자는 읽고 작성할 수 있습니다. 운영자는 Supabase에서 부적절한 게시물을 삭제할 수 있습니다.
- Supabase 설정 전에는 배포된 사이트에서 편지 등록을 막고 연결 준비 안내를 표시합니다.

## 편지 수정·삭제 및 관리자

- 작성자는 편지를 올린 브라우저의 저장소에 있는 편지별 권한으로 수정·삭제합니다. 브라우저 데이터를 지우거나 다른 기기를 사용하면 작성자 권한을 사용할 수 없습니다. 이전 방식으로 등록한 편지는 관리자가 관리할 수 있습니다.
- Supabase Authentication에서 행사 관리자 계정을 만들고 사용자의 UID를 확인합니다. SQL Editor에서 아래 문장을 실행해 그 계정에만 관리자 권한을 부여합니다.
  ```sql
  insert into event_private.admins (user_id) values ('관리자-계정-UUID');
  ```
- 사이트 하단의 관리자 모드에서 해당 이메일과 비밀번호로 로그인합니다. 관리 권한은 데이터베이스에서 검증되며, 공개 API는 발신자와 수정 권한 정보를 반환하지 않습니다.
